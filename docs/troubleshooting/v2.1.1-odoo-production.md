# v2.1.1 Odoo Production Troubleshooting

## Could not get input with given index

This is a v2.1.0 Request Builder topology defect. Install v2.1.1 and import the v2.1.1 canonical workflow; do not manually add hidden input connections.

## check_access_rights does not exist

This is a v2.1.0 preflight compatibility defect. v2.1.1 uses public `fields_get` and read-only probes instead.

## Recipient remains PROCESSING

Do not rerun the full sender path. Check `writeback_queue`. A pending bundle is repaired before the next provider job. If no bundle exists, preserve the row for manual review because provider side effects may be uncertain.

## Campaign paused

Read `campaign_report.Pause_Reason`, the provider status, and the affected job. Correct the root cause, then start a controlled run with the same campaign/job data rather than clearing sent rows.
## Retry says provider credential reference is unavailable

Use the Phase 01 canonical workflow. After `Wait Before Retry` or `Wait Before Failover`, the path must read the provider Sheet, execute Provider Loader, and then re-enter Provider Selector. A workflow that connects the retry Wait directly to Invoice Sender is an older topology and can lose the process-local credential vault after a long wait or worker/process change.

Check that both rehydration Google Sheets nodes use the native Google Spreadsheet, the `provider` tab, and the same Google Sheets credential as the initial provider read.



## Campaign already has an active run lease

Check `campaign_report.Run_ID`, `Run_State`, and `Lock_Expires_At`. If another n8n execution is active, let it finish. If the prior execution stopped, first verify its n8n execution state and pending writeback queue; wait for expiry or deliberately reset the lease only after confirming no provider path can resume.

## Mixed pending campaigns found

The canonical workflow processes one `Campaign_ID` per execution. Move the other campaign rows out of the pending set or mark only one campaign ready. Do not bypass the check by removing `Campaign_ID`, because the default campaign value can still mix unrelated rows.

## Campaign lease verification failed

The workflow writes the lease and rereads it before provider selection. A verification failure means another execution may have overwritten the row or the Sheet write/read result was inconsistent. No provider operation should have started. Stop both runs, reconcile `campaign_report`, and restart only one campaign execution.

## Version or issuer preflight block

`ODOO_VERSION_UNSUPPORTED` means the server major is not 18 or 19; do not override the result. `ISSUER_MISMATCH` means at least one enabled account in the failover group has a missing/different `Issuer_Key`, a different authenticated Odoo company, or configured company evidence that disagrees with preflight. Correct the provider rows or Odoo user company access, then rerun. Do not manually route around the group block.

## PROVIDER_PENDING operation envelope
A `PROVIDER_PENDING` row means InvoiceRouter durably recorded intent before provider work. On rerun, reconcile by stable Odoo reference and repair Sheet writeback; do not blindly resend or recreate the invoice.

## Stale report writer rejected

A campaign/account report candidate did not start from the Sheet's current `Revision`, or the campaign `Writer_Run_ID` no longer owns the active lease. Preserve the pending operation/writeback envelope, stop overlapping executions, and compare `Base_Revision`, `Revision`, `Run_ID`, and `Writer_Run_ID`. Do not copy the older totals over the newer row. On the next controlled run, already-applied stale repair payloads are skipped; a revision gap remains blocked for manual reconciliation.

## Issuer mismatch account-report row

Rows with `Campaign_ID=PREFLIGHT` and `Issuer_Mismatch=TRUE` are diagnostic preflight evidence. Compare `Issuer_Key`, `Company_ID`, `Company_Name`, and `Disabled_Reason` across the failover group. Correct the provider/Odoo company configuration and rerun preflight; do not delete the row to bypass allocation blocking.

## Phase 07 gate failures

- Engine smoke failure: confirm public npm access, exact n8n 2.31.6 resolution, package build, and custom-extension discovery. Review `evidence/phase07/n8n-engine-smoke.log`.
- Canary/pilot gate failure: do not edit evidence values to force PASS. Correct the Odoo, Sheet, envelope, revision, or inbox discrepancy and rerun the reviewed test.
- Short-secret text corruption: confirm the Phase 07 boundary-aware redaction source is installed and rebuild/restart n8n.


## Engine smoke fails with `spawnSync npm.cmd EINVAL`

This identifies the pre-corrective Phase 07 Windows launcher. Apply the final corrective delta. The corrected harness invokes npm through the active Node executable and `npm_execpath`, then imports/exports the complete canonical workflow.

## Unresolved PROVIDER_PENDING after restart

Do not clear the row or rerun a sender-only node manually. The corrected workflow reconstructs the operation using `Stable_Reference` and `Profile_ID`, rereads the campaign lease, and asks Odoo for a matching invoice before any create/send action. A recovered posted invoice without trusted email checkpoint is `UNVERIFIED` and must be reviewed rather than resent.

## Provider-side-effect lease changed

The immediate pre-sender lease check detected a different Run_ID, inactive lease, or expiry. No new provider operation should begin through that path. Stop overlapping executions, reconcile `campaign_report` and `writeback_queue`, and resume only one execution for the Campaign_ID. Google Sheets is not an atomic lock service, so the one-active-execution rule remains mandatory.

## Duplicate email-list row after identity initialization

The final corrective workflow must show `Google Sheets - Persist Job Identity` as an **Update Row** operation matched on virtual `row_number`. If an older workflow matches the initial write on `Row_ID`, do not run production bulk: a blank source `Row_ID` can append a second row instead of updating the original. Re-import the corrected canonical workflow.
